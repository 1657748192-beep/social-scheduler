## 实施裁决与代价

- Redis 中日期编码为 ISO、读取时校验并还原，避免失效时间被误判；解码错误应失败关闭，不猜测有效期。
- 回调可携带原 workspaceId 与随机 syncId 供前端拒绝工作区不匹配，两者都不能单独授权访问；路由错误只报错，不自动切换工作区。
- 已接受的确认固定所选集合直到原 TTL，不允许取消改选，同集合可重试并由数据库锁防重；代价是已接受的选择无法编辑，界面应明确提示。
- 新账号 capabilities 中记录本次 pageSyncImportId，用于提交／Redis 应答丢失后的结果核对；不修改旧账号。计数错误风险由重复／丢失应答测试覆盖。
- 完成结果在 Lua envelope 内保存为不透明 JSON 字符串，避免 Redis cjson 将空数组变成对象；回归测试检查 0 个跳过等结果形状。
- 同步路由优先处理专用 state，不改普通绑定 controller；伪造或无效同步 state 不得落入普通更新流程，相关 HTTP 测试覆盖。
- importing 视图只返回此前已接受的公开主页 ID，用于刷新后重试同一选择；不返回 token，不选择其他新主页，服务端选择摘要仍校验。
- 唯一一次独立整分支审查安排在部署前；部署产生的证据独立核对，不能为了严格按任务序号而先部署再安全审查。
- 刷新恢复仅在标签页 history 中保存随机 syncId、workspaceId、会话令牌 SHA-256 指纹；不保存令牌或候选，读取仍校验服务器会话／工作区。代价是换会话后不能恢复旧同步。
- Meta 授权页面原有主页勾选由用户控制，新增提示保留原选择；本地不覆盖不能阻止用户在 Meta 撤权，忽略提示可能使旧授权失效。
- 2,000 项是有界输入上限，不承诺真实网络在 60 秒内完成；超时整体失败而非部分导入，代价是大量主页可能需重试。
- 线上保护证据由部署执行者另行核对，不用代码审查替代。漏核对会使保留承诺不可验证，因此激活检查失败即停。
- 普通重新绑定仍保留其原有凭据更新行为；只新增请使用“同步公共主页”，否则用户主动重新绑定可能更新凭据。
- 原有头像／名称自动同步不改动；只新增不会覆盖旧授权／凭据／排程，但既有资料同步仍可能正常更新展示信息。
- Meta 在最后校验之后撤权无法与本地事务原子锁定；保留选中凭据校验及发布时校验，代价是之后被撤权的新主页可能需要重连。
- 审查的 ID 类型问题按实际影响升级为 Important 并修复，无延后的小问题。
