# Inbox read verification — 2026-10-22

## Approved boundary

Local implementation and tests only. No Meta requests, deployment, production API/Worker restart, permission changes, credential replacement, or schedule changes. Existing authorization fences and duplicate/unknown-send protection remain mandatory.

## Changes

- Coalesce identical Facebook token inspections only inside a single read operation. Runtime/credential epoch and token hashes isolate evidence. No successful evidence survives into another HTTP request; writes bypass the read cache. Session, workspace, selection and grant checks remain before/after remote inspection.
- Share negative rate-limit backoff within the API runtime. Token-inspection and engagement-read limits enter the same gate; respect bounded Retry-After and exponential fallback. Limits remain retryable, not missing credentials or a successful empty inbox. This in-memory gate is not a distributed Redis configuration change.
- Propagate account-level rate status through list/capabilities/refresh, including HTTP 200 partial results. Pause manual and automatic reads until the retry window. Recheck on recovery.
- Successful synchronization reloads the selected detail. Transient limits hide previously loaded provider/customer bodies and disable writes while retaining local reply/note drafts and unknown-send blockers. Actual access loss still clears protected data/drafts. Scope changes reject late responses.
- A detail reload also observes its own retry deadline and a parent-level cooldown.
