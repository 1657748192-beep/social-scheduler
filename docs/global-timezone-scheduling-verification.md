## 当前状态

主要功能已本地实现：国家／地区、代表城市与 IANA 时区搜索，当地日期时间、夏令时重复候选、当地与北京双预览、最多8个隔离收藏、API 保存时区、日历详情及已发布记录核对。

**尚不能标为全球时区完全可用：本机及测试浏览器的部分规则落后于 IANA 2026e。受影响地区已阻止新排程提交，不会猜测时差。此项仍是发布阻断，未部署、未推送。** 若改用随网页打包的完整规则数据或更换换算引擎，按已批准计划需先取得用户对设计调整的确认；本轮没有擅自引入。

## 实施范围与保护

- 所有提交来自同一个已确认 UTC instant。多账号任务共用这一时刻；API 不按 timezone 再次换算。
- 旧客户端缺省时区仍为北京。立即发布和草稿不携带定时字段；无效非空输入不会偷偷变成草稿。
- 查看、切显示时区、无变化保存均不发 PATCH。原记录秒／毫秒保留；仅文本保存省略 timezone，让 API 保留原值，包括不可识别的旧值。
- 日期控件最早日期按目标时区今天计算。日历格子、查询范围和拖拽仍按北京解释，拖拽不覆盖原时区。
- 无 schema migration、回填、db push、旧队列重建或环境更新。Worker 源码、队列契约、授权范围、发布凭据及会员权限代码不变。
- 未连接腾讯云、未重启 API／Worker、未申请权限、未创建云资源或收费服务。没有发送真实社媒帖子、评论或私信。
- 独立本地测试数据库／Redis 中仅使用新建的合成账号与任务。测试进程没有 Worker，只清理当前测试拥有的具体记录和队列 ID；禁止生产回退、flushall、obliterate。

## 独立复核与单次修复

独立只读复核范围 `b46f515..e01cfcb`，无Critical，3项Important：

1. Intl接受不同大小写，精确字符串探针可能漏检。现在通过权威Intl resolved ID及显式目录别名匹配；`america/winnipeg`、`CANADA/CENTRAL`回归由失败转通过。
2. 不能假定客户浏览器已有本机2026b规则。现在执行Almaty2024a、Asuncion2025a、Vancouver2026b语义基线探针，再检查2026c–e变化地区；旧Asuncion规则模拟会阻止提交。探针只是可信性检查，不把固定偏移用于换算，也不是对所有历史／未来规则的全面证明。
3. 规范化时区ID不能把丹麦代表城市变成柏林。目录保留 `sourceZoneId` 和原地区代表城市，按显式历史别名寻找CLDR中文名称；哥本哈根、斯德哥尔摩、阿姆斯特丹、加德满都、加尔各答、基辅及北京检索回归通过。选择共享同一规范时区的城市时，当前表单仍保留用户选中的地区标签。

修复遵循失败测试→修复→定向通过，随后执行最终完整回归；没有再派复核代理重复审查。作者对修复作额外自查，不把它称为新的独立复核。

待优化Minor：长结果列表连续按向下键时，活动选项尚未自动滚入视口；可键盘选择，但可能选择到视口外项目。此项没有混入本轮安全修复。

## 仍需解决的规则限制

本机 Node24.18.0／ICU78.3／tz2026b，测试浏览器对基础探针通过，但不满足以下2026e预期，故网页暂不能按这些地区的当地时间新建排程：America/Winnipeg、America/Edmonton、America/Inuvik、Africa/Casablanca、Africa/El_Aaiun。合法UTC旧任务不改动；其当地显示在规则无法确认时降级北京。API仍按既有契约接收明确UTC及合法IANA标识，不用服务器旧规则重新换算；网页的可信性门禁不冒称为新增的API权限限制。

目录名称版本与规则版本是两回事。IANA2026e／CLDR48.2.3静态目录不会更新浏览器Intl规则。当前实现不能承诺每一个客户端或未来政策自动正确；探针发现异常即拒绝，不使用当前偏移近似未来时间。

## 执行裁定、范围与风险

- 已批准规则：兼容性失败只阻止受影响的新选择及发布验收，不阻断其他可验证地区的本地开发；代价是这些地区需要后续规则方案，不能宣称全球验收完成。
- Task3接口与Composer状态／请求联动提前一起接入，避免新对象被旧北京字符串转换器误用；覆盖最初“最小接线前移”及后续“提交也需同步前移”两条裁定，风险是请求集成回归，已有真实组件及HTTP测试覆盖。
- 文本保存不发timezone，交由旧API保留原值，避免重验未知旧值或写入临时查看地区；风险是依赖省略字段保留原值的API契约，已做回归。
- 新增代表城市来源字段和浏览器语义基线属于原目录／兼容性职责，不另引入换算引擎；风险是探针并非完整时区数据库版本证明，仍保留发布阻断和明确限制。
- 复核未检查的云端数据／凭据／容器状态不通过访问线上补证，本轮只证明没有操作线上；不扩展到既有发布队列并发重构、未来政策保证或付费服务。风险是这些既有问题并未由本功能解决。
- 复核排除的最终测试／浏览器结果由主执行者验证；复核后变更仅为有失败回归覆盖的修复、目录再生成和输入框样式。无关脏文档及输出不提交。

后续必须先确认规则兼容方案，再单独批准部署。若获准部署，顺序API→网页，Worker保持原状；不迁移、不回填、不重建旧排程。回退网页→API，不恢复或删除用户合法新建数据。
