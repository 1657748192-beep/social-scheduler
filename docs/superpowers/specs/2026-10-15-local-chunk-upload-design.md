# 现有服务器分块上传与失败重传设计

## 目标与费用边界

用户上传约 60MB 的视频时进度缓慢，希望减少上传失败后从头重传的浪费。使用现有腾讯云服务器、磁盘、PostgreSQL 和 Redis，实现可重试的分块接收；上传完成后仍生成现有的 MediaAsset，发布与排程继续读取原有格式。

不创建存储桶，不启用 COS、CDN、全球加速、付费带宽升级、自动扩容或其他新增收费服务。不修改平台 OAuth 范围、客户端凭据、账号绑定、发布权限和已有排程，不重启排程 Worker。现有套餐的流量仍按原有规则计量；不能把“不购买服务”解释为超出套餐仍免费。部署前检查可见的余量信息，不进行大流量云端压测；无法确认余量时报告限制，不擅自升级或购买。

本功能改善失败恢复和传输可观察性，不承诺提升运营商或跨境线路带宽，不通过自动压缩或降低画质缩小视频。

## 现状与方案选择

当前本地上传通过 POST /workspaces/:workspaceId/media 接收 multipart 整文件，最大 250MiB。服务器上传接收预算为 30 分钟，浏览器等待为 35 分钟，普通请求接收预算为 5 分钟，请求头限制为 60 秒。现有 COS 分块代码依赖有效存储桶，当前桶检查返回 NoSuchBucket，本方案不启用它。

可选方案是继续整文件重试、在现有服务器收分块，或者使用 COS。整文件重试改动少但仍浪费已上传字节；COS 不符合本次费用边界。选择现有服务器分块接收，不引入新的第三方协议服务或产品依赖。

## 用户操作

首版只将不少于 8MiB 的视频切换为分块上传；图片和小文件沿用原接口，单文件上限仍为 250MiB。

每块 1MiB，最后一块按实际大小。浏览器所有上传任务合计最多同时发送两个分块，避免“两个视频各开多个连接”造成并发膨胀。先以稳定恢复为目标，不默认增加到更多并发连接。

界面区分准备文件、上传、合并确认、失败四个阶段，显示已确认上传量、速度和估算剩余时间。速度不可估算时不显示虚构数值；只有素材最终确认成功才显示完成。

网络错误、408、429 和可重试的 5xx 可对单块最多自动重试三次，采用退避和抖动，并尊重 Retry-After。浏览器单块等待最多四分钟。401 停止任务并沿用登录过期处理；403、413、无效内容和校验不一致不无限重试。自动重试用尽后保留已收块，提供“重试”操作。

重试前查询服务端已确认分块，只补传缺失块。刷新或重新打开页面后，用户需重新选择同一文件；浏览器不能自动重新读取本地文件。文件内容指纹一致且会话未过期时继续已有上传，否则明确提示重新开始。首版不承诺关闭浏览器后后台继续上传。

封面生成是可选步骤，最多等待五秒，不得阻塞视频发送。封面生成失败不使视频上传失败；取消及超时后释放视频元素和对象 URL。

## 上传会话与接口

新增独立的 LocalUploadSession 和 LocalUploadPart 表，仅用于素材上传。现有素材、帖子、账号、授权和排程表不改字段语义。迁移只新增表及必要索引，不批量改写旧记录。

会话记录创建用户、工作区、随机会话 ID、客户端幂等键、原文件名、MIME、总字节数、有序分块 SHA256、文件指纹、状态、预留空间、活动时间、到期时间、合并尝试标识和最终素材 ID。分块记录会话 ID、块序号、大小、校验值及服务端生成的磁盘键，唯一约束为会话与块序号。

客户端幂等键按一次上传意图生成，重复初始化返回同一会话。浏览器只保存待完成任务的会话信息和内容指纹，并按登录用户与工作区隔离，不保存凭据或视频内容。服务端不信任这些信息作为权限证明。

指纹由总大小、MIME 和有序分块哈希计算，不仅凭文件名、大小或修改时间判断“同一文件”。浏览器按块计算哈希，不一次加载整个 250MiB 文件到内存。

全部接口位于 /api/v1/workspaces/:workspaceId/media 下：

| 接口 | 职责 |
| --- | --- |
| GET /upload-capabilities | 返回本地分块是否可用、大小限制、块大小和协议版本，不返回云凭据 |
| POST /upload-sessions | 校验元数据、总大小和块清单，预留容量，幂等创建会话 |
| GET /upload-sessions/:id | 返回状态和已确认块序号，供失败恢复使用 |
| PUT /upload-sessions/:id/parts/:index | 流式接收一个原始二进制块，严格限制实际字节数并校验 SHA256 |
| PUT /upload-sessions/:id/thumbnail | 可选 JPEG 封面，校验文件签名及实际大小，最大 100KiB |
| POST /upload-sessions/:id/complete | 确认所有块后执行幂等合并，返回现有 MediaAsset 响应 |
| DELETE /upload-sessions/:id | 取消未完成会话，只清理该会话残片，不删除最终素材 |

初始化及每次操作都校验有效登录、当前工作区成员关系、当前发布权限、可写角色和会话创建用户。知道随机 ID 也不能跨用户或跨工作区读取、写入、合并或取消。权限中途失效时停止接收，不绕过现有账号管理规则。

每个块的长度、序号及哈希必须与会话中已接受的声明一致。已确认块内容相同则幂等成功，内容不同返回冲突，不覆盖原块。同一块并发上传只允许一个接收者；客户端遇到“正在接收”的冲突时先查状态，而非立即重传整文件。

会话与分块路由在 JSON 中间件之后以独立 raw/流式处理器接收二进制，不提高全局 JSON body 大小限制。单块和普通接口继续采用五分钟请求接收限制；现有整文件上传的 30 分钟例外保持不变。

## 文件隔离与原子确认

残片放在现有持久卷中的私有子目录 .upload-sessions，不允许通过 /uploads 静态路由访问。显式拒绝该子目录及任何路径穿越；磁盘路径只使用服务端生成的 UUID 和受约束序号，不使用客户端文件名拼接路径，不跟随符号链接。

每次接收使用唯一临时文件名，边流式写盘边计算哈希。超过预期字节数立即中止，失败仅清理本次临时文件。验证成功后以不可变磁盘键保存，并在短数据库事务内锁定会话、确认仍可写、插入分块记录。同块并发冲突时只删除本次新文件，不能删除已被确认的文件。

使用现有 Redis 的有界租约限制接收并发：每会话最多两个在途分块，服务端合计最多八个。租约持有者使用随机标识，释放时比较标识，不能释放其他请求的锁；租期覆盖单块接收期限，崩溃后会自动释放。Redis 不可用时拒绝新分块并提示稍后重试，不退化为无限并发。

只有所有块齐全、总大小及各块哈希均一致时才能进入合并。通过会话行锁和合并尝试标识，确保并发 complete 不会重复创建素材。合并流式进行，不将整文件读入内存。每次合并使用独立的输出临时名，校验后原子移动到最终文件名。

最终素材创建与会话 completed 状态在同一事务中提交。只有最终文件存在且验证通过，才创建 ready 素材；只有事务成功，才返回成功并清理该会话分块。返回响应丢失后，重复 complete 返回同一素材，不新建第二条。

合并尝试租约为十分钟。API 重启或尝试超时后，恢复操作先核对数据库状态及尝试标识，只清理失效尝试拥有的输出临时文件；旧进程不能提交或清理新尝试的结果。最终文件已生成但事务未提交时，不直接当作已完成，必须验证其归属与内容再恢复或重建。

MediaAsset 的 URL、storageKey、MIME、字节数和可选缩略图与现有本地素材一致。发布器和排程 Worker 不感知分块协议；它们只会看到已确认的完整素材。

## 资源上限与残片清理

每用户最多两个未完成会话、每工作区最多四个，服务器未完成上传的总预留空间最多 2GiB。每个会话按原文件两倍大小加少量元数据预留，覆盖分块和合并文件短暂共存；在途重复临时文件也受并发与单块大小限制。

容量预留在数据库短事务中使用全局容量锁串行检查，防止并发初始化超卖磁盘。写入前检查现有卷实际可用空间，至少保留 2GiB 安全余量；不足返回可理解的 507 提示，不自动扩容，也不删除用户已有素材以腾空间。磁盘中途 ENOSPC 时不创建 ready 素材。

未完成会话在最后有效活动后保留 24 小时。开始有界分块接收时及成功确认时更新活动时间；不能通过无效探测无限延期。完成响应可在会话中保留 72 小时用于幂等恢复，最终素材仍遵守原有保留策略；若素材已经按原策略过期，应返回过期状态，不能伪造成功。

清理由 API 内独立、低频、受锁保护的任务执行，不改排程 Worker；服务启动后及每小时扫描有限批次。先在数据库领取可清理状态，再删除该会话私有目录中的确切文件。取消时先阻止新写入，再有界等待或终止在途接收，避免清理后请求重新写回。

只清理上传会话目录及可证明属于失效合并尝试的输出文件。不得递归删除 uploads 根目录，不触碰已提交 MediaAsset 的原文件、缩略图和现有帖子素材。API 崩溃留下的无记录私有临时文件，超过 24 小时且无有效接收租约时才清理。清理失败保留可重试记录并记录非敏感错误码，不假报已释放空间；会话占用的容量预留在其残片确实删除前不释放。

## 兼容与部署

通过协议能力查询渐进启用。旧客户端和图片上传继续使用原整文件接口；旧服务器对能力接口返回 404 时，新网页在开始上传前回退旧流程。分块会话已开始后不静默切回整文件上传，以免重复消耗流量和磁盘。

COS 代码不启用、不迁移、不删除；生产配置仍为 MEDIA_STORAGE=local。首次部署只增加上传相关表和代码，使用原有 API、网页服务；不重启 Worker、数据库和 Redis。部署前备份配置及镜像，核对平台权限、排程和 Worker 身份；正常令牌定时刷新需独立核实，不能当作部署改写凭据。

回滚可以恢复旧 API 与网页镜像，新增表暂留而不破坏旧程序。回滚期间已有分块不可由旧程序继续，用户得到明确提示，完整素材和排程不受影响；再次上线后可恢复未过期会话。回滚后遗留私有残片需要按清单处理，不宣称旧 Worker 会自动清理新目录。

## 验收

- 自动测试跨用户、跨工作区、viewer、过期登录与过期发布权限拦截，以及路径穿越、超大块、错误哈希、缺块合并和总大小超限。
- 用真实 HTTP 流、临时磁盘和独立测试数据库验证上传、单块失败重传、相同块幂等、冲突块拒绝、并发 complete 与客户端取消。不能使用正式数据库做隔离测试。
- 模拟响应丢失、API 重启、合并文件生成后事务失败、清理与在途上传并发、磁盘不足及 Redis 故障，验证不存在重复素材、残片重建或误删现有文件。
- 验证 250MiB 上限与边界、1MiB 分块、浏览器总并发两个、单块最多三次自动重试，及非重试错误立即停止；进度不重复累计重传字节。
- 验证刷新后重新选同一文件续传、选不同内容不能串用会话、封面超时不阻塞、网络恢复后只补传缺失块。
- 在本地模拟慢速网络和中途断网，对比原方案与新方案的已确认字节、失败恢复时间和重传字节；不得仅凭更换界面宣称提速。
- 完整回归账号绑定、内容编辑、发布和排程相关测试，并完成 API 与网页构建。线上仅做小文件验证及健康检查，保留最终用户原视频的真实上传验证，不做付费压测。
