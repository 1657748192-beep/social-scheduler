# 统一互动收件箱与客户资料 — 详细设计

日期：2026-10-17。状态：待用户审阅；本文件不是实施授权或上线验收报告。

## 1. 设计意图与确认范围

用户希望一次性设计并建设完整多平台互动后台，后续逐个平台取得权限和验收后启用真实数据，而不是每获批一个平台就重做页面。参考所提供四张截图的评论／私信／@被提及、平台和账号选择、联系人搜索、标签筛选，但沿用 Social Scheduler 自己的样式和工作区体系。

本次确认只允许编写详细设计。不得修改产品代码、数据库、环境、云服务、平台权限、登录配置、Webhook 订阅或审核申请；不发送评论／私信，不执行真实补充授权。设计审阅通过后再编写实施计划，计划经用户批准后才开发；部署仍需单独授权。

后续开发的完整范围：

- 统一入口、五个平台目录、多账号筛选、评论／私信／提及三类视图、三栏交互和手机适配。
- 客户搜索、客户资料、人工客户标签、互动分类、内部备注、处理状态、负责人。
- 独立互动能力与连接目录、统一列表／详情／发送服务、接入适配器契约、去重和发送不确定性处理。
- 复用可验证的现有 Facebook 独立互动服务；其余平台具备明确禁用适配器与能力状态，不伪造可用性。
- 当前阶段页面和全部新接口仅平台管理员可见／可用，并且仍受工作区成员身份限制。

“一步到位”指完整界面、数据结构和接入架构，不指绕过平台审核、一次性保证五个平台都能评论／私信／提及。

硬边界：现有 SocialAccount 发布绑定、OauthCredential、发布登录配置、已获批发布权限、Post／PostVariant／Schedule／PublishJob 记录及发布 Worker 均不由本功能改写。不新增收费资源或外部收费服务。BM 主页管理仍独立保留，不把业务资产管理混入客户聊天。

## 2. 项目现状和方案选择

本地代码基线 `eda9253`，保留工作树已有未提交文档和截图。本次只新增本设计文档。

- `apps/web/app/facebook-inbox/page.tsx` 已使用 PlatformAdminOnly，当前是公共主页 Messenger，不是 Facebook 个人账号私人聊天。
- `components/inbox/FacebookInbox.tsx` 按工作区、managedPageId、connectionId 读取会话；现有选择与迟到响应保护可复用。
- `apps/api/src/facebookManagement/` 已有独立连接、资产目录、访问控制、评论／私信读取、发送尝试和接收处理。API 进程已有专用接收 pump，不需要让发布 Worker 负责互动。
- Prisma 已有 FacebookManagementConnection、FacebookManagedPage、FacebookInteractionEvent／Comment／Thread／Message／SendAttempt；旧 FacebookReceived*、InstagramReceived* 数据并存，不得因新入口自动重新暴露。
- 当前支持账号平台为 Facebook、Instagram、TikTok、YouTube、Pinterest。不因参考图出现 X、LinkedIn、Threads 就新增这些平台或承诺其能力。
- 现有独立互动能力仍须按账号和真实链路验收，历史文档、平台批准记录、缓存 scope 都不是“当前可用”的充分证据。

比较三种方案：只改 Facebook 页面名称无法支撑多平台客户索引；复制五套收件箱会重复状态、鉴权和客户功能；推荐“统一互动域＋薄平台适配器＋复用现有 Facebook 服务”。共享业务规则，平台差异留在适配器，避免把 Facebook Page ID／24 小时等特定规则硬编码为全平台规则。

## 3. 信息架构和页面布局

新主路由 `/inbox`，侧栏名称“互动收件箱”，继续放在原 Facebook 收件箱位置；BM 主页管理位置不变。旧 `/facebook-inbox` 保留兼容入口，仅在完成管理员和工作区校验后转入新页、预选 Facebook。已有帖子评论入口可携带不可信定位参数进入统一页面，服务器重新校验归属。

桌面层级：

```
工作区                     评论 | 私信 | @提及
全部平台 | Facebook | Instagram | TikTok | YouTube | Pinterest
账号选择(已选 N)     时间／状态／标签筛选     刷新／同步状态
客户／互动列表      原帖或会话、回复区域      客户资料／标签／内部备注
```

- 顶部账号目录显示头像、名称、平台、授权状态；支持账号名／规范用户名搜索、单选、多选、“选择本次筛选结果”。最多同时选择 50 个账号，目录按 50 项游标分页，计数明确为全目录还是当前筛选结果，不把第一页冒充全部。超过 50 时要求缩小范围，不静默漏查。
- 未选择账号时不隐式查询全部；首次进入选择当前工作区该平台可读账号（不超过 50 个），这是读取过滤，不触发授权、导入、订阅或发送。没有可读账号时展示目录及禁用原因。
- 平台切换清空先前的客户、正文、分页和回复上下文；账号多选只用于汇总读取，不支持一次回复多个账号。
- 三类标签始终可见；无对应能力时明确解释，保留切换其他账号入口。
- 列表行显示客户、来源账号／平台、摘要、时间、未读提示、处理状态、标签。评论按客户＋原帖＋根评论组织，私信按会话组织，提及按平台事件组织；不把同一客户的多个帖子混成一条可回复会话。
- 中间评论显示原帖链接／已授权预览、父评论与回复树；私信显示时间顺序消息；提及显示来源和官方链接。回复仅面向明确选中的一项。
- 右侧客户资料默认折叠次要字段；手机按列表→内容→客户资料三级导航，返回保留当前有效筛选；360px 不横向溢出。
- 中文为默认，中英双语沿用现有语言体系；平台图标配可读名称，键盘焦点、Escape、加载和错误状态可访问。没有数据不展示宣传轮播冒充功能完成。

## 4. 客户资料、搜索和标签

客户实体属于工作区，初始每个受作用域约束的平台身份单独对应客户。身份键至少包括 workspaceId、platform、providerAppId／ID namespace、providerAssetId 和 providerActorId；Page-scoped ID、不同应用的用户 ID 不交叉拼接。没有稳定平台身份时，仅创建该互动的匿名参与者展示，不根据昵称创建可跨会话匹配的身份。

- 展示平台实际提供的头像、昵称、用户名、主页链接、首次／最近互动时间和可见互动记录；空字段显示“平台未提供”，不猜测邮箱、手机号、所在地、粉丝数。
- 客户搜索匹配当前可访问范围内已同步的昵称、用户名、人工备注及客户标签；搜索不是全网人物搜索。提供独立“搜索消息内容”选项，默认关闭；限当前可访问的索引化正文，不实时扫描全平台。
- 标记搜索范围与数据截至时间。姓名重复显示来源账号、平台和身份区分信息。
- 客户标签：潜在客户、批发客户、已成交、重点跟进等，管理员可自定义名称和安全颜色；不自动批量生成预设标签记录。
- 互动标签：询价、售后、投诉、合作、无关；与客户标签分表、分筛选。情绪“积极／中性／消极”是人工可选分类，不自动推断。
- 标签名称 1–30 字符，工作区内分类后规范化唯一；每个客户／互动最多 10 个标签，单工作区最多 200 个活跃标签。重命名保持 ID；删除需确认，只删除标签及关联，不删除互动／客户，不调用平台。
- 备注最多 2,000 字符、纯文本，单客户最多 100 条有效备注；显示作者和时间。内部备注提交与公开回复采用不同入口、不同接口和显著配色，绝不复用发送请求。
- 首版不提供客户跨平台合并／拆分 UI，不按同名自动合并；保留将来可审计的身份关联扩展点。该功能需独立设计，不能把一次错误合并泄露为另一身份的历史。

## 5. 处理状态与负责人

互动处理状态为 `pending / in_progress / resolved`，与“是否回复”及每位管理员的已读状态分开。回复成功不自动视作问题解决；平台确认的新入站内容将已解决项重新置为 pending，迟到的旧事件不重新打开。

已读使用每用户每互动的最后已读事件位置，不因另一管理员打开而消除所有人的未读。未读计数只统计确知未读的数据，失败／未连接时显示不可用而不是 0；跨账号计数有失败分区时显示“部分账号不可用”。负责人只可选该工作区内当前有效的平台管理员成员；成员失效后显示“负责人已失效”，不能作为数据访问凭证。

允许批量标记处理状态或标签，最多 50 项，每项单独复核权限并返回成功／冲突／不可访问结果。首版不批量发送、自动回复、群发或自动分配负责人。

## 6. 平台能力与启用规则

能力至少分为 `comments.read/reply`、`messages.read/reply`、`mentions.read`，提及回复不定义独立通用发送能力：仅在可精确映射到评论／消息且该项可回复时走原能力，否则只提供官方链接。点赞、删评、隐藏、拉黑、附件发送、陌生人主动私信、广告评论均不在本版。

每项能力分别记录：产品开放状态、适配器支持状态、应用批准状态、账号真实授权状态、资产角色／task、授权有效期、最近验证结果、实时平台约束。服务器推导最终可读／可回复和中文原因。审核未知不能写成“审核中”；本轮不自动更新平台审核状态或声称查询到了开发者控制台结果。

| 平台 | 本版框架准备 | 真实能力默认边界 |
| --- | --- | --- |
| Facebook | 接入既有独立 Page 目录、评论／私信适配服务 | 逐主页验证真实可读／可回复，提及默认未接入；不支持个人私聊 |
| Instagram | 评论／消息／提及禁用适配器与独立连接槽位 | 不恢复旧退役路由或旧接收泵；获授权和完成接入验收前不开启 |
| YouTube | 评论适配器契约和目录槽位 | 官方有评论读取接口，但本应用授权及回复能力另行验证；私信／提及不假定可用 |
| TikTok | 三类占位能力、独立接入槽位 | 现有发布／Display 授权不作为互动授权证明，不复用 Sandbox 凭据 |
| Pinterest | 三类占位能力、独立接入槽位 | 未核实可用的官方接口前保持“待接入／能力未确认”，不是“审核中” |

账号与能力状态文案区分“未接入”“暂未开放”“待核实审批”“需要补充授权”“授权失效”“平台不支持”“同步失败”“可用”。未接入账号不产生伪造消息；空成功响应必须来自已启用且完成真实读取的适配器。测试夹具仅本地／隔离测试数据库运行，不写入线上客户表。

后续开放要求全部满足：官方接口适用→实现与测试完成→应用权限状态确认→用户明确补充授权→精确资产身份验证→真实读取验收→发送另行验收。每个平台每项能力可独立停用；浏览器不能通过传 `enabled=true` 激活。

## 7. 独立互动授权和发布保护

Facebook 继续使用现有 FacebookManagementConnection／FacebookManagedPage 与明确的选定连接，不复制 token。其他平台准备独立 InteractionConnection／InteractionAsset；占位目录记录只有资料和状态，没有 token。

从 SocialAccount 只读构建账号目录，通过同工作区、平台、规范资产 ID 精确匹配；不按名称匹配。展示“已绑定发布”和“互动连接”两个独立状态；未绑定发布的资产沿用现有 Facebook 必须发布绑定的访问规则，不在本次悄悄放宽。

统一模块禁止写 OauthCredential、发布 OAuthState、SocialAccount 发布状态和 capability scopes；不读发布 token 作为互动回退；不刷新发布凭据。独立互动断开只停用该连接，不调用撤销整个应用权限的接口，不删除发布账号，不改排程。Meta 等同应用的远端授权可能相互关联，未来实际授权前必须明确说明资产选择影响，不能承诺本地隔离就阻止平台侧撤权。

本轮设计的授权入口仅显示状态与所需能力说明，补充授权按钮为禁用状态，文案“待单独确认后开放授权”。不增加 OAuth scope、回调配置、应用权限或自动订阅。已存在的 Facebook 连接仅在原有能力与开关允许时使用，不因进入新页面自动扩权。

## 8. 后端模块与持久化边界

建议 `apps/api/src/interactionInbox/` 分为 access、capabilities、directory、contacts、labels、cases、reads、sends、reception、adapters。每个模块只负责一个边界；UI 采用 InboxPage／Filters／AccountPicker／List／Detail／ContactPanel／CapabilityNotice，而不是在旧 FacebookInbox 中堆五个平台条件。

新增逻辑实体（在后续实施计划明确 Prisma 字段和迁移）：

- InteractionConnection／InteractionAsset：非 Facebook 的独立授权与资产；token 仅密文；唯一键包含工作区、平台、应用命名空间、资产／连接。Facebook 通过 sourceRef 引用原管理表，不双写凭据。
- InteractionCustomer／InteractionIdentity：工作区内客户和平台身份；头像／URL 只是显示资料，不是身份或权限证明。
- InteractionCase：工作区、资产、类型、平台线程／根评论／提及 ID、来源引用、参与身份、最近入站时间、处理状态、负责人、版本。唯一键包含工作区、规范资产键、kind、providerThreadOrEventId。
- InteractionItem：归一化正文索引、方向、事件 ID、父事件、平台时间、接收时间、删除标记、来源引用；去重键包含资产命名空间及事件 ID。Facebook 正文由原服务持有，新模块只引用读取，不复制第二套正文；case／搜索视图通过服务器查询组合。
- InteractionTag、CustomerTag、CaseTag、CustomerNote、ReadReceipt：全部带工作区边界；关联写入必须检查两端同工作区。标签／状态使用乐观版本避免覆盖另一个操作者的编辑。
- InteractionSyncState、InteractionSendAttempt、InteractionAudit：记录受限游标／修订、幂等发送结果、操作者及脱敏结果。Facebook 发送继续复用现有 SendAttempt，不建立第二套可重发状态机。

不在本次设计执行 migration。未来仅新增表／索引和兼容性字段，不重命名或删除现有发布表，不搬移旧 token。旧 Facebook／Instagram 接收存量默认不迁移；现行 FacebookManagement 数据只在访问复核后可作为当前 source 读取和建立索引，不导入已退役的 Received* 表。新索引按需、有界建立，禁止部署时全量扫描历史。

## 9. 平台适配器契约

统一服务把服务器解析出的 ConnectionContext（不向浏览器序列化 token）传给适配器：

- `capabilities(context)`：返回逐项证据及限制，不将“请求过 scope”当作已授予。
- `list(context, kind, cursor, limit)`／`detail(context, sourceRef)`：返回规范项、安全游标、来源时间、可继续分页信息及逐资产警告。
- `reply(context, target, text, requestKey)`：返回 sent／failed／unknown，只有支持的能力可调用。
- `normalizeVerifiedEvent(event, context)`：仅处理已在原始字节上验签、核对 app／asset 的事件；不接受前端提交的“Webhook JSON”。

未实现适配器返回结构化 `not_integrated`，不是空数组；每次平台调用限定固定官方 host／path，不跟随客户端 Graph URL。游标不可携带未验证的跨租户上下文，限长并签名绑定工作区／资产／筛选摘要；筛选变化后旧游标 400。请求超时、响应大小、分页总量和并发均有上限，限流遵从平台 Retry-After，不以循环重试掩盖失败。

## 10. API 与鉴权

新 API 命名空间 `/api/v1/workspaces/:workspaceId/interaction-inbox`：

- GET `/capabilities`、`/accounts`、`/cases`、`/cases/:id`、`/customers/:id`、`/customers/:id/notes`、`/tags`。
- POST `/refresh`：只对已选且已启用的资产请求有界读取，返回分资产成功／失败，不修改权限。
- POST `/cases/:id/replies`：严格正文、显式目标和 UUID requestKey；不存在“对当前筛选全部发送”的接口。
- PATCH `/cases/:id`（处理状态／负责人／版本）；POST `/cases/:id/read`；POST `/cases/batch`（仅处理状态／标签）。
- POST `/tags`，PATCH／DELETE `/tags/:tagId`；PUT `/customers/:id/tags`、`/cases/:id/tags`；POST `/customers/:id/notes`、DELETE `/customers/:id/notes/:noteId`（删除本人备注，平台管理员工作区 owner/admin 可删除其他人备注，均审计）。

身份检查顺序为有效登录会话→服务器配置识别的平台管理员→有效工作区成员→角色→目标资产及互动独立授权→能力和实时约束。平台管理员不是任意工作区超级访问令牌。viewer 最多只读；editor 可处理／备注／人工回复；owner/admin 可管理标签／独立连接。当前普通客户即使是工作区 owner/admin 也返回 403，未知或其他工作区目标统一 404。

复用现有服务器 ADMIN_EMAILS 判定；不新增普通客户可编辑的管理员字段、不扩大白名单、不靠前端布尔值鉴权。新路由、旧兼容路由、统计／搜索／标签／备注接口均覆盖相同门禁；不因为查询本地缓存就绕过资产授权。未来客户开放需另行批准和权限矩阵测试，本版无自助开关。

GET 无副作用，不导入账号／授权／订阅；所有目标由服务器存储关系解析。API no-store，日志不含消息正文、客户姓名、token、原始签名、备注或 OAuth code；诊断仅返回随机 diagnosticId 和安全错误码。

## 11. 搜索、分页与失效一致性

列表按最近互动时间＋稳定 ID 倒序，游标分页 25 项、最大 50；跨账号查询使用已授权本地索引或有界接入读取，不为每个翻页发起全账号全历史抓取。消息搜索词 2–100 字符，纯参数化查询；300ms 防抖，服务端限制每用户每工作区每分钟 30 次搜索。索引覆盖工作区、资产、kind、时间及规范姓名／标签；不引入收费搜索服务。

查询返回 accountsStatus、partial、observedAt、lastSuccessfulSyncAt，失败分区不能显示 0 条或计入完整统计。初次失败显示重试；刷新失败保留同一上下文已显示内容并标记过时。失去工作区成员／管理员／资产访问权限后清除正文、搜索结果、客户摘要及草稿，不保留可继续读取的缓存。

浏览器请求绑定 token 会话、工作区、账号选择、kind 和 case；切换时 abort＋世代检查丢弃迟到响应。回复草稿仅内存；切换或退出如有未发内容先确认，取消切换保持原上下文。不得将客户正文／备注存 localStorage、URL、分析 SDK。URL 只放经校验的定位 ID，不放姓名、搜索词、凭据或正文。

## 12. 发送、安全接收与同步运行

发送前显示平台、账号、客户、公开评论／私信类型；公开回复与内部备注视觉和按钮文字分离。服务器再次核验会话、成员、连接版本、资产归属、实时能力、回复目标和平台要求的窗口，不信任列表加载时的结果。

requestKey 绑定工作区、资产、目标及正文摘要。重复同 key 同正文返回原结果，不再发送；不同目标／正文同 key 返回 409。平台明确成功才标为 sent；超时或断线造成 unknown 时禁用自动重发，提供官方入口核对；人工核对后可解除本地待核对状态，但不能伪造 provider 成功 ID。本版本仅文字回复，平台长度由适配器返回并由服务器校验，不采用全平台统一长度。

Webhook 保留既有验签和连接路由；无稳定身份、跨工作区映射不明、失效连接、不能验签的事件拒收或隔离，不猜测接收账号。仅已启用的平台可以启动处理；先可靠记录再确认、去重再归一化、每批最多 50 项、租约与有界退避，重放不重复入库或重复发送。读取和事件处理重试不能触发人工回复重试。

统一页只订阅本地修订／每 30 秒可见页刷新；隐藏页面停止，网络失败退避。每个已选账号人工刷新冷却至少 30 秒、全局受平台配额限制，不能靠开多个标签页绕过。首次无远端权限不启动扫描；不自动订阅所有账号、回补所有历史或默认后台持续抓取。

互动接收沿用 API 内独立 pump；新增平台的 pump 默认关闭，不修改发布 Worker。未来是否拆分独立互动服务另行评估，本版不创建新机器、队列服务、桶、AI 或付费搜索。

## 13. 隐私、删除与留存

客户备注、标签和索引只供当前有权管理员成员使用，不公开到社交平台。内容纯文本安全渲染；平台 URL／头像走 HTTPS 官方来源白名单，拒绝任意服务器代理 URL，防 XSS／SSRF。

新增互动原始事件默认最长 7 天，新增归一化内容最长 90 天；平台条款或删除要求更严格时取更短期限。此值只是产品上限，不宣称满足每个平台政策：适配器启用前必须审核其允许留存／删除规则，尚未审核的不持久化真实数据。既有 Facebook 原服务留存本版不扩大；客户索引不得延长原数据存活时间。

本地客户备注／标签默认保留到工作区删除或管理员主动删除；依赖的平台身份若被删除请求覆盖，关联本地资料同步纳入该请求处理，不以“人工填写”绕过删除。退订／断开后停止读取与事件归属，并立即禁止旧内容访问；按平台更严格规则执行清除。支持管理员删除本地客户资料，需确认、审计且不删除平台用户或发布记录，不因收到一个伪造外部删除 ID 就跨工作区删数据。

## 14. 错误与运营可见性

错误码至少为 forbidden、not_integrated、not_open、authorization_required、authorization_expired、unsupported、rate_limited、provider_unavailable、reply_not_allowed、send_unknown、stale_cursor、version_conflict。管理员可见“最近成功同步、受影响账号、建议操作、诊断编号”，客户资料和正文不进运维日志。

新互动功能有独立只读／发送开关，默认未启用的能力不调用平台。停用统一新入口不影响原发布 API、上传、排程或 Worker；单平台失败不拖垮其他平台目录与本地标签／备注操作。历史已失权资产的客户资料也不可通过标签统计反查。

## 15. 验收标准与后续开发分解

完整框架作为一份实施计划拆为有依赖的小任务，而不是缩减为 Facebook 单页面；UI、客户域、平台契约、Facebook 包装、其他禁用适配器、保护验证均在计划范围。每个平台真实启用是框架完成后的独立授权／审核／验收阶段，不与当前计划的完成混淆。

必须覆盖的测试：

1. 五个平台、三类视图、20 个以上账号目录、搜索／多选／50 上限、桌面三栏和手机三级导航。
2. 未接入、无权限、失效、平台不支持、失败、真实空数据、部分失败和过时数据文案各不混淆。
3. 普通客户页面直达与每个新 API 均被拒；平台管理员非成员、viewer 写入、跨工作区 case／客户／标签／备注、游标重用、迟到响应均失败关闭。
4. 同名不同资产／平台客户不合并，备注不外发，标签重命名不丢关联，删除标签不删除内容，失权后搜索／计数不泄露。
5. 事件重放、平台分页重复、并发更新、旧事件迟到、每用户已读、已解决项遇新消息、断开后迟到事件均有确定行为。
6. 每次发送精确目标、能力／窗口复核、同 key 重放／不同正文冲突、超时 unknown 禁止自动重发；预览／筛选／刷新不发送任何内容。
7. 测试前后发布权限记录、密文凭据、绑定、排程、任务、帖子关联快照一致；旧管理员 BM／收件箱保护不退化。完整测试和 API／网页构建通过才允许申请部署。
8. 真实平台验收单独列出：权限证据、资产身份、真实读取、真人授权的测试回复和投递。隔离夹具通过不写成真实平台验收通过。

未来部署若获授权，仅 API／网页及批准的新增兼容迁移；先保护快照和旧镜像，再核对健康／普通客户拒绝访问／Worker 不变。无需重启 Worker；不执行全量历史迁移。回退仅切 API／网页和新入口开关，保留新表，不删用户资料、不倒退发布数据。迁移明细和兼容回退在实施计划中逐项列出，当前不执行。

明确不在本版：自动情绪／意图识别、AI 回复／翻译、快捷回复库、导出、客户跨平台手工合并、批量发送、附件处理、点赞／删评／隐藏、陌生人主动私信、开放普通客户、申请／提交平台审核。负责人和人工标签包含在本版，后续自动化不混入。
