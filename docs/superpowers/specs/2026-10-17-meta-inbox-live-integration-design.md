# Facebook / Instagram 统一收件箱真实接入设计

日期：2026-10-17。状态：待用户审阅；不是实施、部署或平台合规验收记录。

## 1. 目标与已确认边界

用户希望用已上线的新版统一互动收件箱完成真实评论、私信的接收和人工回复，之后从授权开始录制审核视频。测试 Facebook 公共主页为 **Factory Wholesale**，Instagram 专业账号为 **mooyamcosmetic**；用户已确认这两个名称。名字仅用于选择提示，后续必须读取并确认工作区、Meta 应用编号、平台资产编号和账号类型，不能凭同名自动授权或发送。

保留新 UI、顶部评论／私信／@提及、按平台和账号筛选、客户标签和内部备注。前后端仍仅平台管理员且有效工作区成员可访问。现有发布权限、密文凭据、绑定、历史帖子的账号关联、排程和任务不变。不重启发布 Worker，不创建收费资源，不申请权限审核、不提交审核、不发布 Meta 应用、不向真实客户试发。当前文档阶段不修改生产配置。

完成的定义是两平台分别取得“独立授权与身份核验 → 真实测试互动进入软件 → 指定人工回复 → 平台官方页面确认收到”的证据，不是仅构建通过、看到授权页或 Webhook 返回 200。

## 2. 代码现状与缺口

- `interactionInbox/runtime.ts` 的 `policyVerified=false` 同时阻止 Facebook 新客户数据持久化与资产接入。不能简单改成全局 true。
- `interactionInbox/access.ts`、`types.ts`、`sourceLifetime.ts` 的来源结构和生存期判断均绑定 Facebook managedPage。Instagram 需要平台区分的来源契约，不能把 Instagram ID 填进 Facebook 字段。
- Facebook 的 `facebookManagement` 已有独立配置、连接、主页选择、能力判断、接收 pump 和幂等发送执行器。统一适配器目前支持评论、私信，不支持提及；评论只覆盖已验证的软件发布记录，不声称读取主页全部历史帖子。
- `removedMetaEngagement.ts` 拦截已退役的旧 Meta 互动接口；当前 Facebook 独立 Webhook 在退役中间件前注册。Instagram 的旧服务代码仍在，但不能因代码存在就声称线上接口可用。
- 旧 Instagram 补充授权在 `socialAccountService.ts` 中与发布 credential 流程相连，不适合本次“发布凭据不变”要求。旧接收服务按发布账号查找凭据，不作为新独立互动授权的直接可信来源。
- 新版目录、筛选、客户域、发送未知结果保护及管理员隔离已部署；此前浏览器测试为隔离模拟数据，不能代替平台实测。

## 3. 方案比较与选择

1. **独立互动连接，复用已验证组件（选择）**：Facebook 包装现有管理服务；Instagram 新增独立互动连接及适配器。发布域不参与 token 写入。代码量较多，但隔离清晰，便于审核展示及撤销。
2. 直接恢复旧 Instagram 互动接口并使用发布凭据：复用较快，但旧入口、授权和数据访问边界不同，可能更新发布凭据，不采用。
3. 只开放 Facebook、延后 Instagram：风险较小，但不满足此次两平台完整链路目标，不作为本次范围缩减。

两个平台共用既有收件箱服务契约，按 Facebook → Instagram 顺序实施和验收，避免同时引入两个未经验证的平台问题。

## 4. 启用门禁与身份

新增服务端、默认关闭的分平台/分资产门禁：策略核验、测试资产允许、读取允许、发送允许分别判断，不向普通用户提供可编辑开关。允许名单使用 workspaceId + appId + providerAssetId，不使用显示名称。发送允许还需通过本次明确批准的测试对象和正文检查；此处不预先授权发信。

替代全局硬编码策略布尔值时，未配置的平台仍关闭。平台策略证据包含来源、查阅日期、所用产品/版本、留存及删除规则、回复窗口、资产访问规则；无证据不接收/投影真实客户数据。开发测试可注入模拟已验证策略，不把模拟结果写成真实核验。Facebook 原有管理功能不因新门禁变更而扩大访问。

每次读写顺序：有效会话 → 平台管理员 → 工作区成员及角色 → 指定测试资产 → 独立连接及版本 → 实际 scope/资产任务/产品限制。缺少授权显示待授权，不显示零条消息。再次授权、撤销、过期和连接版本变化立即使旧游标及旧数据访问失败关闭。

## 5. Facebook 接入

只使用 Factory Wholesale 对应的独立 FacebookManagement 连接和主页选择，不复制发布 token，不新增发布账号，不覆盖其他主页选择。先只读核实 app、Page ID、连接拥有者、任务、实际 grant、过期时间及通知订阅。

读取/回复继续调用现有 management engagement 服务及发送幂等执行器；不再建立第二套自动重发逻辑。先启用授权范围内的评论及私信读取，发送默认关闭。Graph 拉取与原服务可信 Webhook 接收引用进入统一投影，事件去重绑定 app + page + eventId。

保留评论覆盖范围提示。审核演示选择已验证归属的测试帖子；如果没有适合的记录，报告缺口，由用户选择帖子或另行批准发布测试帖子，不自动新发。不重复发表评论来验证读取。

## 6. Instagram 独立连接与适配器

使用与当前账号适配的 Instagram Login 产品路径，新增独立互动 OAuth 发起/回调、状态、断开及通知状态接口。配置复用已有合法的应用身份时不修改应用密钥；回调白名单和实际用户同意分别留给明确授权的配置/登录步骤。注册回调或点击同意不等于申请平台审核。

独立连接记录至少包含工作区、发起管理员、appId、providerAccountId、状态、版本、实际 scopes、过期时间和加密 token。token 使用现有加密工具，仅服务器解密；不更新 `OauthCredential`、现有 Instagram 发布账号 scope 或刷新 token。一个当前账号通过 app + providerAccountId 关联独立连接，不创建重复发布账号。

OAuth state 单次使用且有过期、会话/工作区/发起人/预期账号绑定；回调重新核验管理员与成员身份。错误账号、缺少必要 grant、state 重放、失权均不写入连接。不要把“请求了权限”或旧 scope 字符串当实际 grant。

已有代码的 `instagram_business_basic`、`instagram_business_manage_comments`、`instagram_business_manage_messages` 仅作候选清单；实施时按实际产品及官方资料验证最小依赖，不顺带请求发布权限或更宽业务权限。如果当前应用配置无法隔离授权或平台不允许目标测试账号，停止该平台实测并报告，不绕过限制。

新增 Instagram 客户端/适配器：资料与资产核验、评论及会话/消息的有界分页、文字评论回复、已有入站会话的文字私信回复。现有纯解析/客户端工具经测试可复用，但不能复用依赖发布 credential 的旧服务。固定官方 HTTPS host，响应/分页/超时/并发有限制，不跟随前端传入 Graph URL。

不包含从评论主动私信、群发、附件、自动回复、点赞或删评。提及未实现仍返回 `not_integrated`，不从普通评论文本推断一个已接通的提及 API。

## 7. 来源契约与增量数据模型

来源改为带 `platform` 判别的联合类型。Facebook 保留 managedPageId/connectionId/version 等现行验证语义；Instagram 使用独立连接、账号、媒体、会话、评论及原接收记录 ID。解析器严格拒绝跨平台字段和未知字段。统一资产唯一命名仍为 platform + appId + providerAssetId。

增量添加 Instagram 独立连接、OAuth state、必要的原始事件/接收正文/发送执行记录；原始事件与正文仅保存一份，统一索引保存来源引用。对同一平台同一账号在多个工作区的映射必须明确，不能广播到所有匹配发布账号。

已存 Facebook sourceRef 使用受限兼容解析器；不更新旧发布表。投影和查询分别检查来源存活、删除标记、独立连接版本、资产归属与策略期限。所有 SQL 来源生存期分支必须加平台条件，禁止 Instagram case 落入 Facebook SQL 分支。

新增兼容迁移仅针对互动域；不删除/重命名既有发布表或迁移旧 Received* 数据。旧 Worker 无需理解新增表，API 内维护不占用 Worker。

## 8. Webhook、同步及删除闭环

Facebook 复用现有独立管理接收器。Instagram 新接收器仅针对明确启用的 app/测试资产注册在旧退役拦截器之前；不整体删除退役保护，不恢复旧的普通客户互动路由。

验证原始请求字节签名、体积、app/recipient 资产映射和事件稳定 ID；未授权/身份不明事件拒绝或不持久化，不能回退使用发布 token。可靠入库后确认响应。API 内有界 pump 处理去重、租约、重放和失败退避，不重启或修改发布 Worker。未启用的资产不订阅、不扫描、不投影。

显示账号级最近成功同步和失败原因，失败不伪装零数据。真实官方样例只能证明样例运输，不作为真人评论/私信到达的证据。若测试账号角色、产品模式或平台可见性限制导致真实数据为空，报告实际错误，不假定“发布应用后自动解决”。

启用前完成删除与留存闭环：到期删除原事件/正文及派生索引；平台内容删除更新来源并清理对应客户缓存；断开先禁读/禁写再按规则清理；app-scoped 去授权/数据删除请求必须验签并核对 app+用户/资产命名空间。一个身份出现在多个资产时只清理匹配范围，不误删其他平台资料。验证受影响客户标签、备注及日志，不借“手工资料”逃避覆盖该身份的删除请求。

留存不超过现有产品上限（原始事件7天、归一化内容90天），平台规则更严取更短；这两个数值不是已核验合规声明。证据不足保持真实持久化关闭。

## 9. 发送与 UI

UI 延续已批准布局。账号授权状态、读取、回复权限及窗口分开显示；内部备注不向平台发送。每次发送明确显示平台、账号、公开/私信、收件人；服务端发送前再次读真实目标、独立 grant 和允许窗口。

Facebook 沿用既有执行器。Instagram 原子领取 requestKey，绑定工作区、资产、连接版本、目标和正文摘要；同 key 同内容返回原结果，不同内容冲突。平台未知结果不重发，网络错误不标成功；官方确认前不开始另一条测试回复。客户端窗口提示不替代服务端判定。窗口值以实施时核验的平台规则为依据，不凭本设计硬编码或借用其他平台例外。

完成框架不自动向客户开放。审核测试账号是否需要临时、受限的管理员入口单独设计/批准，不扩大 ADMIN_EMAILS 或给予任意工作区超级访问。

## 10. 测试、上线和实测阶段

实施测试先写失败用例：平台来源隔离、独立 token 不触碰发布 credential、错误账号及 OAuth 重放、普通客户/非成员/viewer、过期/撤销、策略未核验默认关闭、签名伪造/重复事件、删除传播、来源生存期、幂等及 unknown。真实 React 测试覆盖授权提示、平台切换丢弃迟到响应、草稿保护和备注隔离；真实浏览器覆盖桌面/手机与两平台筛选。

独立测试库验证迁移前后发布账号/凭据、排程/任务/帖子快照一致。完整回归与 API/web 构建通过后报告证据，不把本地模拟测试当真实平台结果。

未来上线单独确认：现有 TAT 通道，先快照/回退镜像，再只更新 API/网页及批准的新增互动迁移，不重启 Worker/数据库/Redis/代理。不创建收费资源。只读验证生产快照、健康、默认关闭/管理员拒绝和 Worker ID/启动时间。回退只切 API/web 镜像，不删除新表、不还原覆盖发布数据。

实测按顺序逐项授权：

1. 用户确认平台资产编号和角色；服务器仅报告脱敏 grant/订阅/状态，不输出 token。
2. 必要时用户完成独立 OAuth 同意；仅对两测试资产执行批准的订阅，保留已有字段，不改变发布授权。
3. 用户或指定测试参与者创建入站评论/私信；记录软件读到的真实编号和账号归属，不收集无关客户正文。
4. 展示测试收件人/帖子与确切回复正文，获确认后每项仅发送一次；未知结果先人工核对。
5. 在官方页面确认回复收到，分别记录 Graph 读取、Webhook 到达、软件显示、发送回执和官方收件证据。缺一项不称对应链路完全通过。
6. 验收后制作从授权开始的录屏脚本与审核材料；不在本阶段点击提交审核。
