# Facebook 分享链接增量导入公共主页：详细设计

日期：2026-10-20。状态：设计待用户审核；未实施、未部署。

## 1. 目标、约束与成功定义

工作区所有者／管理员生成专用链接，交给另一个 Facebook 账号持有人；对方在 Facebook 官方页面登录并授权，只生成临时候选目录，不自动绑定。链接创建人在软件原工作区勾选新增公共主页并确认后，才创建新发布账号及凭据。

用户明确要求：已有主页全部跳过，不覆盖其权限、凭据或排程。本设计将“不覆盖”扩展为完整旧记录保护：账号状态、头像、名称、capabilities、credential、历史关联、postVariant、schedule、publishJob、独立 BM／互动连接及订阅均不更新。已有但断开或失效的主页也跳过，不隐式恢复。共同管理的主页按工作区、平台、Page ID 去重，不按个人账号或名称去重。

首版仅 Facebook。普通客户中拥有工作区 owner/admin 资格的用户可以发起，不要求平台管理员身份；导入后的发帖／排程仍遵守现有会员发布权限和工作区角色。对方无需软件账号，不能借链接查看工作区账号或操作后台。新增的所有主页都必须来自对方本次真实授权，并由创建人显式勾选。

本阶段仅编写设计；不修改 Meta Login Config、不申请权限、不授权真实账号、不改生产数据、不重启 API 或 Worker、不部署。后续实施／部署需单独批准，不新增收费资源。

## 2. 当前实现依据与方案选择

核查依据：当前分支基线 b10eff5。

- `services/socialAccountService.ts`：旧分享链接 24 小时有效；`startSharedOAuth` 进入普通 OAuth。Facebook 回调枚举返回主页，直接 upsert SocialAccount 和 OAuthCredential；会更新已有主页 token、scope、状态和资料，没有返回软件后逐项选择的阶段。
- `facebookPageSync/*`：已具备独立 state、候选目录、分页校验、手动多选和锁内“存在即跳过”。当前上下文绑定发起人的 user/session/workspace，候选仅 15 分钟有效，不能把它的私有接口直接开放给外部持链接人。
- `SocialAccountManager`、`DashboardPageContent`：已有统一社交账号入口，可增加专用分享入口与待确认任务区，不新增全局菜单。

比较三种方案：

1. **推荐：独立邀请与待确认任务，复用窄化后的只新增导入内核。** 旧分享流程不变；跨用户安全边界清楚，支持授权后创建人稍后回来确认。需要新增邀请持久化与专用路由。
2. 直接改造所有旧分享授权。改动较少，但改变旧 Facebook 重新绑定语义，容易影响其他平台及既有凭据刷新，不采用。
3. 把现有同步 URL 分享出去。会把内部登录会话和导入权限混同，且 15 分钟候选寿命不适合异步交接，不采用。

## 3. 页面与用户流程

### 3.1 创建人：生成邀请

社交账号 → 添加账号 → Facebook，提供三个用途明确的入口：

- “本人授权绑定”：保留当前行为。
- “同步公共主页”：保留当前本人会话下只新增同步。
- **“分享链接导入主页”**：新增推荐入口，文案“对方只授权，你来选择；已有主页保持不变”。

旧“分享授权”不得偷偷切换语义；Facebook 上将旧入口标注为“普通绑定授权（可能更新已有绑定）”，不与新入口使用同一个标签或解释。其他平台不改。

创建时显示不可编辑的目标工作区名称，可填内部备注（最多 80 字，不在公开邀请页展示）。固定 24 小时有效，不提供永久链接或后台自动续期。生成后显示链接、到期时间、复制、撤销按钮；不自动发消息或邮件。链接密文能力只在本次生成响应返回一次，之后需要新建邀请才能重新分享，不长期明文存储。

### 3.2 对方：官方授权

打开专用公开邀请页，显示产品名称、创建人允许公开的产品身份说明，不显示工作区名称、成员资料或现有主页。明确提示：

> 此链接只用于授权读取你允许访问的 Facebook 公共主页。最终由邀请人在软件中选择新增主页；不会由此立即发帖。密码和验证码仅输入 Facebook 官方页面。

点击“前往 Facebook 授权”后才启动 OAuth；GET、链接预览、爬虫访问不消耗邀请、不发起授权。对方在官方页面核对账号和授权资产；若有已有资产选择，提示不要取消原有选择。软件不代填密码，不主动撤销上游授权，不能保证用户在 Meta 侧手动撤销资产后旧 token 仍有效。

成功后返回专用公开结果页：“授权已收到，请通知邀请人到软件选择主页”。不展示候选列表、旧主页是否存在、导入结果、账号 token；没有“确认导入”按钮，不要求登录邀请人的软件账号。一个邀请只接受一次成功授权；错误、取消允许在有效期内重新开始，已生成候选后不可被第二个 Facebook 账号替换。

### 3.3 创建人：待确认与多选

社交账号页增加紧凑“分享导入任务”区域：创建时间、内部备注、任务状态、到期时间、“查看待导入主页”及“撤销”。仅创建人且当前仍为 owner/admin 可查看本任务；其他管理员也不能仅凭任务 ID 读取候选。创建人重新登录后可继续处理，不绑定创建邀请时的旧会话，但每次操作重新验证当前有效会话和成员资格。

任务按当前工作区过滤。列表只请求非敏感状态；候选仅在打开详情时读取。手动“刷新状态”，不新增 Worker、轮询作业或外部通知服务。

详情显示本次授权的候选主页名称、头像、Page ID，以及“新增可导入／已存在保持不变／权限不足”。默认不选中任何主页；支持搜索和“全选当前筛选的可导入新增主页”，总选择上限 50 个，跨筛选保留选择并清楚显示数量。已有主页含断开的记录一律禁选。Meta 未提供可验证的授权者昵称时不编造或根据主页名推断个人身份；只显示邀请备注、本次任务和候选 Page ID。

“导入所选主页”先显示确认数量和旧记录不变声明，再提交一次。完成显示“新增 N 个／已有跳过 M 个”，刷新原工作区列表；不自动发布或创建排程。没有新增时显示“这些主页已存在，无需导入”，允许完成空操作并立即清除临时凭据。任务成功后不可再添加另一批选择，需要新邀请。

## 4. 数据模型与保存范围

新增独立的 `FacebookPageImportInvitation` 与必要的选择／结果子记录或等价 JSON 字段，不复用旧 `OAuthAuthorizationLink`；仅增加新表及索引，不修改旧模型列或凭据。使用现有 PostgreSQL、Redis 和加密密钥，不引入新服务。

邀请持久记录包含：随机 UUID、workspaceId、createdById、内部备注、secretHash、状态、版本号、createdAt、expiresAt、authorizedAt、候选截止时间、受控授权摘要、选择摘要、接受的选择 ID、导入结果、非敏感诊断编号、撤销／取消时间。

- 链接 secret 为至少 32 字节密码学随机值，仅存 SHA-256 摘要。随机任务 ID 不是访问凭证。
- 候选 Page ID／名称／头像／实际 scope／token／token 到期时间／授权身份的必要证明作为一个服务端加密 envelope 保存到独立临时记录。每次读取校验邀请版本、状态及截止时间。数据库或 Redis 中均不保存明文 token。
- 目录最多 2,000 个、4 MiB；一次最多导入 50 个。到期＝授权成功后 24 小时或邀请创建后 48 小时，以较早者为准。链接启动期限仍为创建后 24 小时，不因失败重试延长。
- 成功、撤销、取消、失去资格或到期后，立即使凭据不可读；成功／撤销／取消同步清除加密候选。到期由 API 机会式、限量清理物理 envelope；没有请求时可保留不可访问的加密过期记录，不能声称到期必然已物理删除。部署验收必须测试清理入口；不依赖 Worker 或新增收费定时服务。
- 非敏感任务结果保留 30 天，之后由同一受限清理机制移除。结果只保存 Page ID、创建／跳过状态和关联的新账号 ID，不保存个人 token 或消息内容。超出保留期不再承诺原任务的重试回执，但唯一键和“存在即跳过”仍防止覆盖。
- 只有临时通过校验所需的授权凭据可以保存；个人／系统用户 token 不写入长期发布凭据，导入仅保存新主页 token。

## 5. 服务与接口边界

新增 `facebookPageImportInvitations` 模块，负责邀请能力、外部 OAuth 握手、待确认状态和授权者到创建人的交接。旧普通绑定、旧分享授权、独立 BM／互动模块均不调用它。

从现有同步实现提取两项小接口：

1. 候选发现与实际凭据校验：固定 Graph 主机、分页、防重放、身份／app／资产／scope／期限证明；不写业务账号。
2. 只新增导入事务：输入已核准候选、显式选择、当前操作人上下文、稳定 importOperationId；返回新增／跳过明细。旧本人同步继续使用自己的会话／15 分钟寿命和错误协议，不能因为复用内核而放宽旧边界。

拟定接口契约（最终路由以实施计划为准，不得更改安全语义）：

| 接口 | 调用者与作用 |
| --- | --- |
| `POST /workspaces/:id/facebook-page-import-invitations` | 当前 owner/admin，创建本人邀请，返回一次性分享 secret |
| `GET /workspaces/:id/facebook-page-import-invitations` | 当前创建人，分页读取本人的非敏感任务状态 |
| `GET /workspaces/:id/facebook-page-import-invitations/:inviteId` | 当前创建人，获取安全候选／结果，不返回 token |
| `POST /workspaces/:id/facebook-page-import-invitations/:inviteId/confirm` | 当前创建人提交 Page ID 数组，二次确认后仅新建 |
| `POST .../:inviteId/revoke` | 当前创建人撤销，不能撤销已提交完成的新发布账号 |
| `POST /facebook-page-import-public/exchange` | 持链接人交换邀请 secret 为短期官方授权流程；不返回候选 |
| 既有 Facebook OAuth callback 的新专用 state 分发 | 校验邀请、浏览器 flow、state 后接收候选；绝不进入旧 upsert 分支 |

公开页面使用 `/facebook-page-import#<secret>`：fragment 不发给服务端；页面去掉 fragment 后，仅将 secret 放在同源 HTTPS POST body 中兑换，内存持有，不写 localStorage／sessionStorage／analytics。公开页面禁第三方脚本、追踪及自动预取，响应 no-store、no-referrer；只使用第一方静态资源。生产代理／应用日志必须验证不记录请求 body、OAuth code、state 或敏感 query，不仅靠前端清理。

交换后服务端下发只对本次流程有效的 Secure、HttpOnly、SameSite=Lax flow cookie（随机引用，不是 token），授权 state 最长 10 分钟、一次性消费并绑定 flow、邀请版本和固定回调。cookie path 必须覆盖同源公开入口和现有回调，不能覆盖无关域；处理同浏览器多标签竞争时，只允许同邀请一个活跃 flow，其他尝试明确冲突，不能串接任务。拒绝、取消、失败或过期后清除 flow，可在邀请有效时重新开始。

公开 start/exchange 严格校验 Origin、同源 POST、防自动重放和按 IP／邀请摘要限流；请求和日志脱敏。外部 callback 不依赖邀请人的浏览器 session，不接受浏览器提交 workspaceId／creatorId／scope／候选 token，也不因持邀请 secret 允许 confirm 或列出任务。

## 6. 状态机、撤销与恢复

邀请状态：`awaiting_authorization → authorized_pending_selection → importing → completed`；旁路为 `revoked`、`expired`、`cancelled`。授权中 flow 是独立短期状态，不允许单次浏览器错误永久占用邀请。OAuth 兑换中的瞬时故障返回可重试失败；同一 code 不盲目重用，必要时从新 state 开始。

链接成功授权后 secret 不再启动新 flow；授权持有人不能改写已保存的候选。创建人撤销时以数据库行锁／版本号与 callback、confirm 串行；撤销先提交则 callback／导入失败关闭；导入先提交则撤销返回“已导入，不能撤回”，不删除新账号或撤销整应用授权。

创建人被移出工作区、降级、禁用后，每次公开交换、callback、详情、确认均拒绝；失效前已在 Meta 点击允许但尚未保存的凭据不得落入可导入候选。成员恢复资格不自动复活已撤销任务。登出旧会话不撤销整个邀请，但导入必须有创建人新的有效登录会话；与旧本人同步会话绑定行为明确区分。

复用现有 Meta grant fence／数据删除边界：按 app 与真实授权主体记录授权开始时间和接收时间，在保存候选及确认前拒绝已被删除／撤销截止线覆盖的旧授权。原应用去授权／数据删除处理必须纳入新邀请的加密候选清理及失效，不能仅清理旧发布账号；删除动作的具体数据范围沿用现有策略，不借此扩大删除旧账号或凭据。新任务处理不得复活被删除的旧主体或持久化已失效 token。日志不保存删除签名请求原文或凭据。

重复确认采用稳定操作 ID＋排序去重选择摘要。首个有效请求固定选择，之后相同选择只读返回回执，不再发起平台写入或替换凭据；不同选择返回 409。失败重试显示同一选择，不允许前端静默更换。

## 7. 只新增写入与并发保证

确认前重新验证当前创建人资格、候选期限和新主页实际权限／身份。不得仅相信前端“可导入”。所选 ID 必须属于本次完整读取的候选，权限不足的候选不能通过伪造请求导入。

单事务内：锁邀请和操作者资格相关行，按 Page ID 排序取得现有 Facebook 主页 advisory lock，再检查工作区＋platform＋Page ID 唯一记录。查到任何已有记录就跳过；不得调用其账号或凭据 update／upsert。仅不存在时创建 SocialAccount、OAuthCredential 和新邀请导入结果记录。事务内再次检查截止时间及邀请状态；全部新增账号与结果一同提交，任何新增失败整批回滚。

与旧普通绑定／本人同步使用同一主页锁协议和数据库唯一键。并发中先已存在就跳过；新功能本身不得覆盖先提交的旧绑定。旧普通绑定在本功能完成后主动重新授权仍可能按旧语义更新，本功能不能锁住未来所有合法操作；验收“旧记录不变”按操作时点、指定旧记录及无并发外部合法改动衡量，不作无限期冻结承诺。

结果持久化与新账号创建同事务，避免“账号已建但回执丢失”时再次创建或改变选择。Redis 仅做短期 flow、限流，不作为业务事务的唯一并发保证。后续平台复验超时、token 撤销、DB 回滚、浏览器关闭等均不得回退旧覆盖式授权。

## 8. Meta 配置前置条件与现有风险

不新增任何 scope，不更改现有 Login Config／回调白名单。沿用已批准的主页发布授权配置，用专用 state 命名空间在现有 callback 内分发；错误或未知新命名空间必须失败关闭，不能落入旧 completeOAuth。

2026-10-20 已只读核查：生产发布 Login Config `1748083276619458` 包含 `business_management`，它当时为“准备测试”；而 `pages_manage_posts/pages_read_engagement/pages_show_list` 为“可发布”。该限制可能影响非应用角色用户授权。**新邀请功能不能绕过 Meta 审核；在原配置未证明对普通用户可用前，不宣称新客户真实授权已打通。** 本期设计不删除该权限、不代申请；上线验收需单独记录这一前置阻碍。

另一个必须先验证的兼容点：控制台将当前发布配置标为“系统用户访问口令”，现有同步发现逻辑严格要求 USER→PAGE token 和 `/me/accounts`。实施计划必须先用官方文档与只读实际返回证明该配置能返回所需身份／目录；不能直接把 SYSTEM_USER 当 USER，也不能仅放宽 token 类型绕过身份和资产证明。如果当前配置无法完成安全发现，停止真实接入并给出单独的配置方案供批准；不静默换用 BM 配置、提高权限或更换发布凭据。该前置检查不需要实际发帖。

## 9. 错误、用户提示与可用性

- 链接过期／撤销／已使用：公开端统一友好失效页，不泄露创建人、候选或工作区；创建人端显示具体状态。
- 对方取消：提示可在有效期内重新打开；旧账号不变。
- 授权成功但目录不完整、分页失败、循环 cursor、超限、平台限流：不把部分目录当完整成功，不产生可导入任务，提示重新授权或稍后再试。
- 没有任何主页：明确“本次授权未返回可用公共主页”，不自动绑定个人账号。
- 已有主页／已断开旧主页：只显示跳过，若需恢复走原重新绑定流程；不提供“强制覆盖”。
- 提交超时／响应丢失：提示查询同任务结果或重试原选择，不建议重复生成、重新绑定或解绑。
- 工作区切换、退出登录、旧请求迟到：清空私有候选，丢弃旧结果，绝不自动切工作区或提交导入。
- 中英文文案、键盘与读屏支持、分页／搜索／空态沿用现有 UI；不做无关页面重设计。

## 10. 验收标准与测试边界

1. 外部无软件账号的人可通过受控模拟 OAuth 完成授权，看到的只是安全完成页；不能读取候选、确认导入或访问其他任务。
2. 当前创建人可在原工作区、新有效登录会话读取候选，多选 1～50 个新增主页；不选不导入，多个任务来源不混合。
3. 真实数据库回归逐字段比较所有预先存在的账号、凭据、权限记录、历史关联、排程和发布任务，覆盖成功、失败、撤销、到期、并发、重复确认和响应丢失；不仅比较数量。
4. 已存在但断开、同主页多授权者、并发两邀请、与本人同步／旧绑定同 ID 竞争：锁内只新增或跳过，没有 update 旧记录的调用。
5. 覆盖无效／泄露／过期／重放 secret，邀请或 state 调包、浏览器 flow 不符、跨工作区／跨创建人、已降级／被移除／禁用，callback 与撤销并发、member 变更与导入并发、候选过期中途事务，以及 CSRF／限流。
6. 覆盖多页和 20+ 主页、缺少发布权限／Page token、app/actor/asset 不匹配、数据过期或撤销、恶意 next URL、循环 cursor、部分页失败、4 MiB／2,000 上限、SYSTEM_USER 与 USER 误配，任何情况均不自动写旧绑定。
7. 针对新旧分享授权、新旧本人同步路由分发做回归，新 state 不得进入普通 upsert。前端测试覆盖误选已有主页、默认不选、确认数量、重复提交、跨工作区迟到响应及分享链接从 URL 清除。
8. 测试先行、独立测试库、完整测试、API 构建、网页生产构建及独立审查通过后才讨论部署。不真实发帖、回复、自动授权或改排程；任何人工外部授权验证需用户亲自操作。
9. 线上普通客户 OAuth 是否通过单列为真实验证项目，模拟测试通过不能替代；如果受 `business_management` 或 token 类型限制，标记受阻，不声称已全面可用。

## 11. 后续实施／部署边界

本文件审核通过后再编写实施计划并选择执行方式，不在本轮开始实现。后续预计涉及 API、网页及只新增数据库表迁移；不需要 Worker 新版本、环境新密钥或新收费资源。

部署需另行确认。只更新 API 和网页，迁移仅创建独立表和索引，不改旧表数据、不启动 Prisma reset/db push 或重跑历史数据。部署前后核对 Worker 容器／镜像／启动时间、原环境摘要和受保护旧数据快照。回退旧 API／网页时可保留新表不使用，不删除已合法导入的发布账号或旧数据；完成的导入不能以部署回滚为由撤销。

## 12. 不在范围

后台自动导入／定时发现、外部持链接人自行勾选和绑定、自动选择个人账号或保存密码、管理员跨用户接管任务、多个授权来源合并到一个邀请、更新／恢复已有主页、替换发布凭据、评论／私信开放、新权限申请或 Meta 审核提交、删除 BM 资产、收费通知／存储服务。
