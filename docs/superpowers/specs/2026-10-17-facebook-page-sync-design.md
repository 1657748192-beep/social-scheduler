# Facebook 公共主页增量导入设计

## 目标与确认范围

在社交账号页增加“同步公共主页”，让工作区所有者或管理员通过官方授权取得候选列表，再手动勾选新增主页导入。不先解绑，不覆盖已有主页的权限、凭据、状态、资料、历史关联或排程。普通客户也可使用此发布账号功能；不依赖仅平台管理员开放的 BM 管理／收件箱。

用户已确认功能方向及 API、网页部署范围。本文件明确新增的两阶段导入安全边界；审核此设计后再编写实施计划，产品实现和部署尚未开始。

## 当前代码证据

- `services/socialAccountService.ts` 的普通 Facebook OAuth 回调会对返回的所有主页执行账号和凭据 upsert，会更新已有凭据，不能直接作为“只新增”同步。
- 当前主页获取只处理一页 `/me/accounts` 响应。同步必须遍历分页，否则无法可靠处理大量主页。
- 普通绑定保存的是各主页 token，没有可长期读取个人账号所有主页的独立用户 token。因此第一版点击同步会走官方授权，不能承诺免授权或后台自动发现。

## 用户流程

1. 在社交账号页显示独立“同步公共主页”按钮，仅工作区所有者／管理员、Facebook 已配置时可操作。说明“仅导入新增主页，不更新已有绑定；需要 Facebook 官方授权”。
2. 点击打开当前应用现有 Facebook 官方授权流程，不解绑、不申请新的 scope 或变更 Login Config。只将必要的临时同步上下文保存在服务器。
3. 回调只读取候选，不创建或更新账号。返回社交账号页，展示当前工作区的候选主页名称、头像、已有／新增状态。默认不勾选任何新增主页；已有记录不可勾选。已有但断开的记录也跳过，避免静默恢复。
4. 用户勾选新增主页，点击“导入所选主页”。确认窗口说明新增数量、旧绑定不变。服务端仅导入本次授权候选中的所选 ID。
5. 返回“新增 N 个，已存在跳过 M 个”，重新读取账号列表。取消、无候选、没有新增、过期、权限不足或平台故障均有明确提示，旧账号保持不变。

## 服务端边界

- 新增独立同步服务／路由，不更改普通添加账号的 upsert 语义。沿用现有回调 URL，在普通回调逻辑前按服务器生成的专用 state 命名空间分发；不得通过用户可控 query 参数切换为普通绑定或跨工作区写入。无需在 Meta 控制台新增回调地址。
- 启动、查看候选、确认导入、取消均校验有效登录会话、当前用户、工作区及当前 owner/admin 资格；查看或写入不能仅凭 URL 中的同步编号授权。回调使用一次性随机 state，兑换前重新核实发起者会话和成员资格。
- 复用现有 Redis，独立键前缀，临时记录绑定 userId、sessionId、workspaceId。授权 state 最长 10 分钟，候选及加密主页 token 最长 15 分钟；不延长现有登录会话。取消或导入成功删除候选敏感内容，过期自动失效。Redis 不可用时失败关闭，不回退到覆盖式绑定。
- 仅使用现有服务器加密密钥在服务端保存临时候选凭据。不把用户／主页 token、scope 原文或 OAuth code 返回浏览器、存入 localStorage、URL 或日志。回调响应 no-store、no-referrer，清理页面回调参数。回调 URL 中仅携带不具独立访问权的随机同步编号和通用结果。
- 候选获取复用当前 Facebook 版本及授权配置，校验实际账号身份、实际授予的发布所需权限和主页 token；不凭“已连接”推断可发布。不得修改用户现有的 Meta 权限选择，不自动撤销权限或订阅 Webhook。
- 分页仅向固定 Graph 主机发请求，使用校验后的 cursor，不直接请求返回的任意 next URL。处理重复 ID、循环 cursor、超时、限流、部分分页失败；完整读取失败时不得把部分结果当作完整目录或自动导入。最多读取 2,000 个主页，达到边界明确报错而非截断成功。
- 浏览器提交严格校验的主页 ID 数组，单次最多 50 个，去重；所选 ID 必须全在当前有效候选中。候选允许用户重新登录另一个 Facebook 个人账号，以导入其有权管理的新主页，但仅作用于发起时的工作区。
- 确认导入时重新检查候选期限、登录／成员资格与权限。利用现有 Facebook 主页锁及数据库唯一约束，按主页 ID 排序加锁。锁后查到任意已有记录即跳过，不调用已有账号／凭据 update 或 upsert 的更新分支。
- 单次所选新账号及其新凭据在数据库事务内创建，写入失败回滚整次新建，不改旧记录。必须处理重复点击、两个同步流程及普通绑定同时导入同一主页：只有首次创建者写凭据，其他请求跳过或返回既有结果。
- 数据库提交后响应丢失或 Redis 结果保存失败时，重试不得覆盖已创建的账号，也不得重复创建；返回新增／跳过的实际结果。Redis 锁不能作为唯一写入安全保障。
- 不写 schedule、publishJob、postVariant、旧 oauthCredential、独立 FacebookManagementConnection 或 PageSelection。只为新主页创建正常发布所需账号及凭据，不自动发布测试帖子。

## 前端边界

- 中英文文案，沿用现有弹窗、按钮和授权方式；“添加账号”与“同步公共主页”清楚分开。
- 同步页身份、工作区、请求序列绑定；切换工作区、退出登录或关闭窗口后，过期回包不得渲染到新上下文或自动执行导入。
- 不默认全选，不导入未勾选主页；正在提交时禁用重复提交。支持明确取消、过期后重新授权，以及无新增主页的空态。
- UI 的“已有”只是提示，最终以事务内数据库检查为准。只读角色没有启动、勾选确认或取消他人流程的控件。

## 验收与回归

- 测试先行：先观察缺少只新增保护、会话隔离、分页或选择控制的测试失败，再实现。
- 独立测试库逐字段比较所有旧账号、旧凭据、历史关联、排程和任务，覆盖成功、取消、失败、重试和并发；不仅比较数量。
- 真实 HTTP 测试覆盖未登录、viewer/editor、跨用户／会话／工作区、被移除或降级的管理员、过期和重放 state、伪造候选 ID、重复确认及数据库提交响应丢失。Meta 网络使用受控响应，禁止真实发表评论或发布。
- 列表测试覆盖多页、超过 20 个主页、缺失权限／token、重复 ID、循环 cursor、恶意 next URL、限流及后续页失败。任何失败均不改变旧绑定。
- 真实组件交互测试覆盖按钮可见性、选择及确认、已有记录不可选、0 新增、取消、失败提示、重复点击和工作区切换后的迟到响应。
- 默认完整 `npm test`、API TypeScript 构建、网页生产构建全部通过后，才准备部署。

## 部署与回退

- 使用既有腾讯云服务器、Redis 与 TAT 通道，不新增资源、收费加速、权限范围或环境密钥，不依赖 Worker 更新。不需要数据库 schema 迁移。
- 只构建 API 和 web，`up -d --no-deps api web`。API 短暂重建，不重启 Worker、数据库、Redis 或代理。
- 部署前保留 API／网页旧镜像、环境摘要及受保护数据快照；部署后核对 Worker 容器／镜像／启动时间、环境摘要、旧账号／凭据／排程快照不变。新同步流程上线本身不导入任何真实主页。
- 核验公网新资源、API 健康及不带授权的拒绝行为；如果真实 Facebook 授权验证需要用户参与，明确记录该项待验证，不将本地模拟称为线上授权成功。

## 不在本期范围

后台定时同步、长期保存个人账号 token、自动全选／全量导入、更新或恢复旧绑定、BM／收件箱权限开放、申请新 API、改现有发布或排程规则。
