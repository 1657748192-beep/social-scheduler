## 执行裁定与代价（完整记录）

- 原设计／计划中的“仅设计”阶段已由用户明确批准实施所取代；只本地修改，绝不把确认扩大为部署授权。
- 4MiB限制包括重复base64封装，比只限原始JSON更严；超大未来版本可能拒绝，需要重新评估，保护内存预算优先。
- API容器cgroup不能证明Redis容器余量，maxmemory=0保守停用缓存；此决定在预检和复核处均有记录，代价是某些现有主机不会自动启用更新，但内置规则一直可用。
- 在22项针对性基线通过后开始隔离引擎工作，同时等待完整基线；当时仍需面对其他基线失败的风险，之后1030项完整基线已通过。
- 新增精确锁定的MIT js-sha256依赖，不自写密码学，不在浏览器引入Node crypto；代价是少量额外依赖，生产审计为0漏洞。
- 循环表只支持到最后已展开转换，不假称2499年底或无限将来均可用；部分极远日期会被明确阻止。
- Docker API／网页复制共享workspace包，确保运行时软链接存在；未构建容器或更新Worker，实际容器启动仍未现场验证。
- 纯时间帮助函数为旧调用保留不可变内置基线默认参数；真实编辑器各处显式传同一快照，新消费者需遵守这一约定，不使用可变全局规则。
- 生成器用完整性锁定npm包的同源原字节，替代易超时的在线标签下载；仍锁版本／SHA256，运行时新数据可用性由受限更新器负责，不声称网络永久可用。
- 候选包在API有界内存中验证，Redis仅保留active／previous，不创建临时包键；减少缓存占用，代价是检查期间一份临时内存副本。
- 缩短循环覆盖的政策需人工审核新基线；代价是这类更新不是完全无人干预，优先避免截短数据被当成永久偏移。
- 历史锚点只冻结已过去样例，不冻结未来政策；代价是未来规则仍依赖官方发布质量，并非逐政治事件人工认证。
- 生成基线、来源与许可证文件用窄范围LF属性固定，避免Windows干净检出破坏字节检查；不改其他文件换行习惯。
- 线上容量、启用状态、容器／Worker运行和费用情况未超范围访问；不能把本地证据当作线上状态或零流量费用认证。
- 最终完整测试、构建与浏览器证据由主执行者取得，独立复核没有代为认证；未来上游不可用或政策变化仍保留原规则，不承诺无限正确。
